# GlandersWatch

A modular platform for glanders risk prediction, retrieval-augmented explanation and owner alerting.

Built as a B.Tech project at the International Institute of Information Technology, Bhubaneswar.

**Authors:** Pedapatruni Shanmuk Vardhan (B123089), Shaktimayee Mohanty (B123118), Yuvraj Singh (B123153)
**Supervisor:** Dr. Sangita Dhara

This repository holds the code only. Reports, figures and assembled data are generated by the pipeline and are not versioned here.

---

## What the code does

Three components around one prediction:

| Component | What it does | Status |
|---|---|---|
| Risk engine | Country-year probability that glanders is documented next year, from 8 selected features | Built and evaluated |
| Explanation layer | Retrieval-augmented answers grounded in official guidance, with citations | Specified, not deployed |
| Alert service | Threshold, suppression and deduplication rules turning a probability into messages | Specified, not deployed |

## Target

The model predicts a binary outcome: whether glanders is **documented in a country in the following year**. One row is a country-year. The 8 features are covariates of that country-year; the country code and the calendar year are identifiers, not predictors (see below).

## Results

| | |
|---|---|
| Modelling rows | 2,880 country-years, 160 countries, 2006-2023 |
| Positives | 169 (5.87%) |
| Features | 8, chosen by SHAP on the training years only |
| Temporal holdout | train 2006-2017, test 2018-2023 (960 rows, 74 positives) |
| Champion | logistic regression, leave-country-out PR-AUC 0.381 |
| Best temporal | random forest, PR-AUC 0.495 |

The two schemes disagree on purpose. Random forest wins the forward split; logistic regression wins when whole countries are held out, which is the deployment case, so it is the champion.

The eight features, with units:

| Feature | Unit |
|---|---|
| `pop_total` | persons |
| `years_since_last` | years (99 = no event in window) |
| `temp_mean_anom` | °C from that country's prior-year mean |
| `internet_pct` | % of population |
| `humidity_anom` | % RH from baseline |
| `precip_cv` | ratio, sd / mean |
| `log_livestock` | ln(1 + livestock units) |
| `goats` | head |

## Reproducing

```bash
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt

python src/01_fetch_data.py
python src/01c_extract_faostat.py
python src/02_build_panel.py
python src/shap_select.py
python src/03_train_evaluate.py
python src/05_dataset_analysis.py
python src/04_report.py
python src/06_analysis_figures.py
```

Outputs land in `data/processed/` (the panel and the feature matrix) and `reports/` (metrics as JSON, predictions, figures). Neither directory is versioned.

`03_train_evaluate.py` takes about five minutes on a laptop.

## Two things that must stay in sync

`reports/selected_features.json` records which features the models use, and `11_export_model_matrix.py` reads it to write the matrix. Run the export after any change to the selection, or the artefact will describe a different model from the one that ran.

`03_train_evaluate.py::load_level1` applies the row filters, and `05_dataset_analysis.py` imports it rather than keeping its own copy. Do not reintroduce a private filter.

## Why the country code and year are not features

Both are identifiers. A country code cannot transfer to a country the model has not seen, which is the deployment case, and in-sample it memorises reporting capacity, the confounder the results chapter identifies. The calendar year tracks reporting growth rather than disease: 65% of recorded events fall in the last five years of the window because open-access publishing grew, not because incidence did.

`14_year_target.py` tests the year explicitly. Regressing the event year on the eight features gives a negative R² (−0.10 linear, −0.10 forest) against a predict-the-mean baseline, so the year carries no usable signal about where or when glanders appears.

## What this problem is, and is not

It is **supervised classification on panel data with a temporal validation split**, sometimes called spatiotemporal risk modelling. It is not classical time-series forecasting: there is no single series being extrapolated from its own past, the target is binary rather than continuous, and the signal is cross-sectional covariates rather than autocorrelation. The time-series element is only the validation design, which trains on earlier years and tests on later ones so the model cannot see forward.

A genuine "when will it happen" formulation would be discrete-time survival analysis, modelling the hazard of a first report given no prior report, with the 106 never-reporting countries treated as censored. That is not implemented here.

## Contributing

Read this before you touch anything.

**`main` is the integration branch.** Changes land there only by merge, and only the owner merges.

```bash
git clone https://github.com/YuvrajSingh-mist/glandersWatch-demo.git
cd glandersWatch-demo
git fetch origin
git switch -c <your-name>/<what-you-are-changing> origin/main
# work, commit, push your branch
```

For example `aisha/fix-chapter-4-typo`.

### The rules

1. **Create your own branch.** Never commit on `main`.
2. **Edit only files on your branch.**
3. **Never merge.** Not into `main`, not into anyone else's branch.
4. **Never force-push.** Not `--force`, not `-f`. Correct mistakes with a new commit.
5. **Do not commit generated output.** `data/`, `reports/`, `figures/` and the PDFs are rebuilt by the pipeline.
